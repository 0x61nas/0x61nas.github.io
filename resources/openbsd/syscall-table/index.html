Searchable OpenBSD Syscall Table OpenBSD 8.0

This table is derived from the sys.tar.gz source tarball of OpenBSD 8.0, specifically its sys/kern/syscalls.master file. The generator is available on GitHub.

Unlike Linux, OpenBSD keeps one common syscall master file for all architectures, so there is a single table here. The Type column shows the type field of syscalls.master; a single syscall can carry more than one type (for example STD NOLOCK). To learn more, read the intro(2) manual page, or the anonymous CVS page for tracking sources.

Manual links follow the man.openbsd.org per-release pattern (https://man.openbsd.org/OpenBSD-8.0/<syscall>.2). Obsolete (OBSOL), unimplemented (UNIMPL) and reserved entries often have no dedicated manual page anymore.

Click on a row to reveal the arguments list and extra details. Search using the fuzzy filter box or the Ctrl+F. The raw table is also available as CSV.

Careful: on OpenBSD 7.5 and later you generally cannot issue raw syscalls from arbitrary assembly locations. OpenBSD's pinsyscalls(2) mechanism restricts syscall instructions to approved locations inside libc, and a direct syscall attempted anywhere else can terminate your process with SIGABRT.

You can still write assembly for your program's logic and call libc functions from it. For example, x86-64 NASM assembly calling write() and exit() through libc:

; nasm -f elf64 hello.asm && cc -o hello hello.o
global _start

section .rodata
msg:    db "hello, world", 10
msglen: equ $ - msg

section .text
extern write
extern exit

_start:
    ; write(1, msg, msglen) via libc
    mov rdi, 1          ; fd = stdout
    lea rsi, [rel msg]  ; buf
    mov rdx, msglen     ; count
    xor eax, eax        ; (libc takes care of the syscall)
    call write

    ; exit(0) via libc
    xor edi, edi
    call exit
    ; not reached

Type field values (a syscall can have more than one):

  • STD — always included in the system
  • NOLOCK — kernel lock is not acquired when called
  • OBSOL — obsolete, no longer included in the system
  • UNIMPL — unimplemented or reserved, not included in the system
  • INDIR — indirect entry, allows a really varargs prototype
  • NOARGS — included, but no syscall argument structure is defined
  • NODEF — included, but the syscall number is not defined
