ايه هي الـ Garbage Collection ؟

الـ Garbage Collection هي عملية إدارة أوتوماتيكية للذاكرة (automatic memory management)، وبتستخدمها معظم لغات البرمجة الحديثة زي Python, Java, Golang..etc عشان تسهل عملية تطوير البرامج من غير ما نهتم بتفاصيل الـ low-level memory.


ايه فايدة الـ Garbage Collector

فـ لغات زي الـ ++C/C مفيهاش Garbage Collector فالمبرمج بيكون عليه مسؤولية الـ allocation و الـ deallocation للـ memory؛ لكن ايه اللي هيحصل لو المبرمج نسي يعمل deallocate للـ variables اللي مبقتش مستخدمة؟ أو عمل deallocate بالغلط لـ variable لسا بيستخدم؟

في حال نسيان تنظيف الذاكرة (Forgetting to free the memory):

لما ميتمش تنظيف الـ memory بعد استخدامها دا بيأدي لـ memory leaks، يعني تعمل allocate وتنسا تعمل deallocate، وده بيقلل أداء الكمبيوتر لأن مساحة الـ memory بتقل وكمان يخلي البرنامج vulnerable.

في حال التنظيف المبكر للذاكرة (Freeing the memory too soon):

لما يتم تنظيف الـ memory وهي مازالت بتستخدم في البرنامج، البرنامج هيـ crash لما يحاول يوصل لقيمة مش موجودة، أو يكون في variables بتشير للـ memory اللي تم تنظيفها، وساعتها يحصل dangling pointers (مؤشرات بتشير لمكان غير صالح في الذاكرة).

المشاكل دي بيحلها الـ Garbage Collector، يعني المبرمج مش محتاج يشيل هم تنظيف الذاكرة بعد الـ allocation لأن النظام بيعمل ده بشكل أوتوماتيكي.


تكلفة الـ Garbage Collection

الـ Garbage Collection بيحتاج مساحة إضافية عشان يتابع الـ pointers في البرنامج، لأنه مسؤول عن تتبع عدد الـ references لكل object. لو عدد الـ references بقى صفر، يبقى الـ object مش مستخدم، وبالتالي يتم مسحه (freeing).

أثناء عملية الفحص دي، الـ Garbage Collector ممكن يوقف تنفيذ البرنامج مؤقتًا عشان يمسح الـ objects غير المستخدمة، وده سبب إن الأداء في بعض الأحيان يكون أسرع في اللغات اللي مفيهاش Garbage Collection.
